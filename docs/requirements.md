# 요구사항 정의 (1단계 사전 분석)

- 작성일: 20261016
- 상태: 초안. 운영 서비스 연결 없이 공식 문서만으로 분석했다.
- 기준: 작업 지시서의 확정 사항. 별도의 마스터 요구사항 문서는 작업 폴더에서 찾지 못했다. 지시서 내용을 마스터 요구사항으로 간주하며, 원본 문서가 따로 있다면 대조해야 한다.

## 2. 기능별 분류

### F1. 대시보드 공통
- F1-1 오늘 화면: 오늘 일정, 중요 메일, 오늘 회의록을 한 화면에 요약한다.
- F1-2 날짜 이동: 이전/다음 날짜와 날짜 선택. 표시는 `YYYYMMDD`로 한다.
- F1-3 반응형 레이아웃: iPad mini 세로(1열), iPad 가로와 PC(2~3열).
- F1-4 연동 상태 표시: 마지막 동기화 시각, 오류, 재인증 필요 여부를 보여준다.
- F1-5 대시보드 로그인: 본인만 접근할 수 있게 한다. 단일 사용자를 전제로 한다.

### F2. Notion 회의록 (읽기 전용)
- F2-1 지정한 상위 페이지 아래의 날짜별 하위 페이지 목록을 수집한다.
- F2-2 페이지 제목에서 날짜를 추출해 `YYYYMMDD`로 정규화한다.
- F2-3 본문 블록을 재귀 조회해 읽기 전용으로 렌더링한다.
- F2-4 변경 감지: `last_edited_time`이 바뀐 페이지만 다시 수집한다.
- F2-5 지원하지 않는 블록은 "Notion에서 열기" 링크로 대체한다.

### F3. Google Calendar (읽기·쓰기)
- F3-1 캘린더 목록과 일정을 조회한다(일/주 보기).
- F3-2 일정을 생성, 수정, 삭제한다. 삭제는 반드시 확인 단계를 거친다. 1차 범위는 **반복되지 않는 단일 일정**이다. 반복 일정은 읽기만 하고 "Google Calendar에서 열기"로 안내한다.
- F3-3 동기화: Apps Script 브리지로 기간 창(기본 -7일 ~ +60일)을 통째로 다시 조회하고 차이만 DB에 반영한다(D-11). syncToken 증분 동기화는 쓰지 않는다.
- F3-4 충돌 방지: 일정의 마지막 수정 시각(`getLastUpdated`)을 비교해, 다른 기기에서 먼저 수정한 경우를 감지한다.
- F3-5 쓰기 작업은 감사 로그에 남긴다. 게스트(참석자)는 추가하지 않아 초대 메일이 나가지 않게 한다.

### F4. NAVER WORKS 메일 (읽기 + 분류)
- F4-1 받은메일함 목록(메타데이터)을 주기적으로 수집한다.
- F4-2 중요도 자동 분류: 긴급, 중요, 일반, 낮음 4단계와 분류 근거를 표시한다.
- F4-3 사용자 보정: 분류 결과를 직접 바꾸면 규칙 개선에 반영한다.
- F4-4 안 읽은 메일 수를 표시한다.
- F4-5 원문은 NAVER WORKS에서 연다. 딥링크 형식은 검증해야 한다.
- 범위 외(1차): 메일 발송, 삭제, 이동, 읽음 처리. API는 있으나 쓰기 권한(`mail`)이 필요하므로 제외한다.

### F5. 백그라운드 동기화
- F5-1 클라우드 스케줄러로 주기 동기화를 실행한다.
- F5-2 재시도: 지수 백오프와 지터를 적용하고 `Retry-After`를 따른다.
- F5-3 토큰 자동 갱신. 갱신에 실패하면 재인증이 필요하다고 표시한다.

### F6. 비기능 요구사항
- 보안: 토큰 암호화 저장, 최소 권한 scope, 단일 사용자 접근 제한.
- 시간대: `Asia/Seoul` 기준으로 날짜 경계를 계산한다.
- 성능: 첫 화면은 캐시된 DB 데이터로 즉시 그리고, 외부 API를 직접 기다리지 않는다.
- 비용: 개인용 규모에 맞게 무료 또는 저비용 등급을 우선한다.

## 4. 의사결정 사항

### 4-1. 확정 (20261016, 사용자가 권장안 승인)

| ID | 결정 사항 | 확정 내용 | 근거 |
|---|---|---|---|
| D-01 | 클라우드 플랫폼 | **GitHub(비공개 저장소) + Vercel Hobby(서울 `icn1`) + Supabase Cron**. 비밀값은 Vercel 환경 변수(Sensitive)에 둔다. (20261016 변경: 처음 확정한 Cloud Run + Cloud Scheduler에서 바꿈) | 사용자가 Google Cloud CLI를 쓰지 않기를 원했다. push하면 자동 배포되고 월 0원으로 운영할 수 있다. Vercel Hobby Cron은 하루 1회만 가능해서 주기 작업은 Supabase Cron이 맡는다. |
| D-02 | 메일 중요도 분류 방식 | **규칙 기반(점수 합산)**. 외부 LLM은 쓰지 않는다. | 회사 메일 내용을 제3자에게 보내지 않는다. LLM 도입은 8단계(선택)에서 다시 검토한다. |

| D-04 | Notion 연결 방식 | **Internal integration**(Read content만) | 사용자가 owner다(C-09). |
